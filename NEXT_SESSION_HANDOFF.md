## Important Design Feedback

The earlier backstage sculptural pass was not the desired artistic direction.
From the side view it still read as a few large clean arcs plus a front scribble.
The desired look is more like a dense intentional tangle: a compact rear knot or
groviglio that feels sculptural from non-camera views, while the privileged
camera still reveals the target.

The current implementation now has a structured `tangle_cloud` connector mode.
The first version was too dense and unreadable from the back view; it was
corrected into fewer loop samples, wider side/vertical spread, and distributed
tangle pockets. The next thing to do is visual inspection and then depth
separation, not a return to large elegant arcs.

The path is now a real closed loop. The generated centerline returns to the
first point, the closing motion is sampled smoothly, and both the profile and
LED previews report `closed_loop: true`.

Latest pass also softened the motion: loop-aware orientation tangents,
longer twist length, cyclic sinuous smoothing, and an anti-spike smoother for
tiny local reversals. This keeps the groviglio but removes some harsh curve and
torsion events.

The leftmost readable component is now restored after the sinuous smoothing
pass. This was added because the `L` in `LOVE` was visually weaker than the
other letters. The restore is generic: it finds the first large white connected
component in the target bitmap and gently raises frontness only for nearby path
points that still have enough target-mask fit.

A broad final clearance pass was tried after smoothing. It reduced collisions
only modestly and made torsion/curvature harsher, so it is disabled now
(`final_loop_clearance_cycles: 0`). The next clearance solver should be local
and zone-aware.

## Target Image Automation

Target selection now lives in `input/target_config.json`.

For the current baseline it contains:

```json
{
  "target_id": "LOVE",
  "target_image_name": "target_LOVE.png"
}
```

If `target_image_name` points to another white-on-black target, most geometry
recalibrates automatically:

- `scripts/00_autosize_config.py` analyzes the bitmap and updates target/lamp
  dimensions.
- Projection, skeleton extraction, path generation, LED mask, camera evaluation,
  validation, and export are regenerated by `scripts/run_all.py`.

Generated debug/export filenames are derived from `target_id`, for example
`continuous_path_LOVE.json`, `camera_evaluation_LOVE.json`, and
`export_manifest_LOVE.json`. The readable preview object also derives its name
from the target id (`AL_READABLE_LOVE_PREVIEW` for the current target).

The project is more generic now, but hard images may still need style and
planner parameter tuning. Those controls should be added to config, not patched
manually into individual scripts.
